# Session 2026-04-13: Major Debugging Session

## Overview

Deep investigation and fixing of apt-get update hang, interactive bash issues,
and rootfs filesystem isolation. Started with apt-get hanging after downloading
InRelease files; ended with the full gpgv verification chain working (method →
fork → dash → apt-key → gpgv).

## Bugs Fixed

### 1. execve ENOENT fallback (commit 029107e)

**Symptom**: Running `vi` in interactive bash gave a nested bash session instead
of "command not found". Missing commands silently re-exec'd the current binary.

**Root cause**: `do_execve` fell back to the current binary for ALL non-ELF files,
including files that don't exist. This broke glibc's `execvp` PATH search — the
first non-existent PATH entry succeeded with the wrong binary.

**Fix**: Return `-ENOENT` for missing files. Only use the fallback when the file
exists but isn't ELF.

### 2. Shebang script execution (commit 920f607)

**Symptom**: Running `ldd` from bash launched a bare shell instead of interpreting
the ldd script.

**Root cause**: Shell scripts (`#!/bin/bash`) aren't ELF, so the "exists but not
ELF" fallback re-exec'd the current binary without the script.

**Fix**: Parse `#!` shebang line, resolve interpreter through rootfs, re-exec as
`fakelinux <interpreter> [arg] <script> <args...>`.

### 3. Symlink resolution in rootfs (commit 5f457fb)

**Symptom**: `cat /usr/bin/which` showed Mach-O binary content instead of the
shell script. Symlinks like `/usr/bin/which → /etc/alternatives/which` escaped
the rootfs to the macOS host filesystem.

**Root cause**: macOS kernel follows absolute symlink targets on the HOST
filesystem. Our rootfs translation only intercepted syscall path arguments, not
kernel-level symlink resolution.

**Fix**: Walk path component by component in `translate_path`, checking for
symlinks at each step. Re-root absolute symlink targets under FAKELINUX_ROOT.
Handles chains with max depth 40.

### 4. readlinkat host fallback (commit 6c7db00)

**Symptom**: `realpath /var/lib/dpkg/status` failed. apt-get printed "flAbsPath
on /var/lib/dpkg/status failed".

**Root cause**: `do_readlinkat` had a fallback that tried the untranslated host
path when the rootfs path failed. `readlinkat("ubuntu-rootfs/var")` returned
EINVAL (it's a directory, not a symlink), then the fallback read macOS's
`/var → /private/var` symlink, pulling realpath into the host filesystem.

**Fix**: Only fall back to host path on ENOENT (file missing), not EINVAL (file
exists but isn't a symlink).

**Debugging technique**: Added path logging to `readlinkat` — saw `/var` resolving
to `/private/var` (macOS symlink) then `/private/var/lib/dpkg` (host path, ENOENT).

### 5. Signal preservation across fork/execve (commit 7e9c173)

**Symptom**: First http and gpgv method children died with SIGINT.

**Root cause**: Three POSIX violations:
- PENDING_SIGNALS not cleared after fork (child inherited parent's pending set)
- SIG_IGN not preserved across execve (fresh statics reset to SIG_DFL)
- Signal mask not preserved across execve

**Fix**: Clear pending signals in `init_child_after_fork()`. Encode SIG_IGN
bitmask and signal mask in `FAKELINUX_SIGIGN` / `FAKELINUX_SIGMASK` env vars
before execve, restore on startup.

### 6. CLONE_CHILD_SETTID in fork trampoline (commit 6e44bff)

**Symptom**: Fork child ran parent code path despite x0=0.

**Root cause**: glibc's `__libc_fork` checks `pthread->tid` after fork. The
Linux kernel writes the child's TID here via CLONE_CHILD_SETTID. Without it,
glibc took a different branch in the child path.

**Fix**: In fork trampoline, after fork(), write child's real PID to
`child_tid_ptr`. Must use real macOS PID (not container vpid — `current_vpid()`
returns the PARENT's vpid since the child hasn't set up its own yet).

Also handle CLONE_CHILD_CLEARTID via `set_tid_address`.

### 7. RwLock poisoning after fork (commit 6e44bff)

**Symptom**: TPIDR instruction lookup failed in fork children.

**Root cause**: `TPIDR_PATCHES_RUNTIME` uses a `RwLock`. If the lock was held
during fork (by the parent's runtime patcher), the child inherits a poisoned lock.

**Fix**: Use `into_inner()` to read through the poison instead of failing.

### 8. Heap allocations after fork (commit 1134edf)

**Symptom**: Fork child corrupted glibc state, ran wrong code path.

**Root cause**: `format!` and `String` in the fork trampoline used heap
allocations. After fork, Rust's allocator may have poisoned locks (inherited from
parent). Heap allocation in the child corrupted the allocator state, which in turn
corrupted glibc's internal `pthread` data during atfork handlers.

**Fix**: Replace all `format!`/`String` with stack-allocated buffers
(`std::io::Cursor` on `[u8; N]`).

**Key insight**: ANY heap allocation between `fork()` and `exec()` is dangerous.
The child should only use async-signal-safe functions (raw `write()`, stack
buffers) until exec replaces the process image.

### 9. Mach-O fallback in rootfs mode (commit 4c93eb9)

**Symptom**: gpgv method's fork child exec'd the method binary itself instead of
the real gpgv tool.

**Root cause**: `/opt/homebrew/bin/gpgv` exists on macOS as a Mach-O binary.
When the method called `execvp("gpgv")`, glibc searched PATH and found
`/opt/homebrew/bin/gpgv` before `/usr/bin/gpgv`. Our "exists but not ELF"
fallback re-exec'd the current binary (the method itself).

**Fix**: In FAKELINUX_ROOT mode, non-ELF files return ENOENT (skip) instead of
falling back. The Mach-O fallback only applies in FAKELINUX_SYSROOT mode
(busybox applet pattern where the guest binary IS on the host).

**How found**: `ps` showed the gpgv tool process running the METHOD binary with
tool arguments (`--quiet --readonly --keyring ...`). Then `which gpgv` on the
host revealed `/opt/homebrew/bin/gpgv` (Mach-O).

### 10. setpgid EACCES after exec (commit 06e167e)

**Symptom**: Commands in interactive bash got "Stopped" (SIGTTOU). Bash printed
`child setpgid (1 to 1): No such process`.

**Root cause**: In our re-exec fork model, the parent's `setpgid(child, child)`
fails with EACCES because the child has already called exec (POSIX forbids
setpgid on exec'd children). The child sets its own group before exec, so the
parent's call is redundant.

**Fix**: Return success when setpgid fails with EACCES.

### 11. xattr syscall stubs (commit fad3960)

**Symptom**: `ls -la` printed "Function not implemented" for every file.

**Root cause**: Extended attribute syscalls (getxattr, listxattr, etc.) were
unimplemented.

**Fix**: Stub all xattr syscalls (5-14). Get returns -ENODATA, list returns 0,
set/remove returns 0.

### 12. Diagnostic tracing improvements (commits c2679a6, 7b81bf2, d6bae26, 97430bf)

Added PID-annotated tracing for read/write/close/pselect6, pipe inode tracking,
fork trampoline register dumps, and instruction dumps at fork resume points.

## Debugging Techniques

- **PID-annotated traces**: `let pid = unsafe { libc::getpid() }` in every trace
  message. Without this, parent/child syscalls are indistinguishable.
- **Pipe inode tracking**: `fstat(fd)` → `st_ino` to verify pipe identity across
  fork/exec boundaries.
- **`lsof -p PID | grep PIPE`** during hangs to verify pipe connectivity.
- **`ps -o pid,ppid,command`** during hangs to see the full process tree.
- **Fork resume PC instruction dump**: Verified glibc's fork wrapper wasn't
  corrupted by our instruction patcher.
- **glibc disassembly via Docker**: Used `docker run --platform linux/arm64` to
  run `objdump` on the rootfs libc.
- **Binary analysis**: Hand-decoded ARM64 instructions to trace glibc's
  `__libc_fork` branch logic.
- **Separate stdout/stderr**: `2>/tmp/trace.log` to avoid mixing trace with
  program output.
- **Stale process detection**: `ps aux | grep fakelinux` to find zombie or
  orphaned child processes from previous runs.
